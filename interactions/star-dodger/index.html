How it's built

A game loop hiding in a portfolio.

The original hides a full arcade game behind one card on a portfolio. Click it and the page dims, your cursor becomes a crosshair, and things start falling. Under the hood it's the classic game recipe: a loop that runs every frame, a list of things on screen, and a collision check between you and each of them.

Ingredients

  • <canvas>Dozens of moving things per frame are cheaper to paint than to move as DOM elements.
  • requestAnimationFrame + delta timeMovement is speed × seconds since the last frame, so it's the same on 60Hz and 120Hz screens.
  • Entity listsPlain arrays of stars, spikes, bombs and particles. Spawn = push, despawn = filter.
  • Circle and box collisionsDistance between centres for stars and spikes; “is the dot inside the square” for bombs.
  • Spawn timers + difficulty rampEach hazard has a countdown; the time between spawns shrinks as the clock climbs.
  • Easing followThe dot moves a fraction of the way to the cursor each frame, which gives it that floaty chase.
  • Web Audio synthEvery sound is an oscillator or filtered noise with a pitch sweep and a volume envelope.
  • Device pixel ratioThe canvas is sized ×2 or ×3 on retina screens so shapes stay sharp.
  • localStorageRemembers your best time and score on this device.
  • Page Visibility APISwitching tabs pauses the game instead of killing you while you're away.

The game loop

Every frame does the same three things: work out how much time passed, update everything by that amount, then draw everything. Capping dt stops a huge jump if the tab hiccups.

function frame(now) {
  const dt = Math.min(0.05, (now - last) / 1000);  // seconds
  last = now;
  update(dt);   // move things, spawn things, check hits
  draw();       // clear the canvas, paint everything
  if (state === "playing") requestAnimationFrame(frame);
}

The player chases the cursor

The crosshair is exactly at the pointer; the dot closes a fraction of the gap each frame. Lower Follow speed = more delay = harder game. The 1 − (1 − k)^(dt·60) form keeps the chase identical at any frame rate.

const k = 1 - Math.pow(1 - config.follow, dt * 60);
player.x += (target.x - player.x) * k;
player.y += (target.y - player.y) * k;

Spawning, with a difficulty ramp

Each hazard has a countdown. When it hits zero we spawn one and reset the countdown to a gap that gets shorter as time goes on. Speeds scale the same way.

const level = 1 + (time / 30) * config.ramp;
spikeTimer -= dt;
if (time >= config.spikeStart && spikeTimer <= 0) {
  spikes.push({ x: rand(0, W), y: -40, speed: 220 * config.spikeSpeed * level });
  spikeTimer = 0.9 / (config.spikeRate * level);
}

Collisions are just distance checks

Stars and spike heads are circles: you're touching if the distance between centres is less than the two radii added together. A bomb blast is a square: you're hit if your centre is inside it (padded by your radius). After a hit you get a moment of invincibility (the dot blinks) so one spike can't take all your lives.

const touching = (a, b) => Math.hypot(a.x - b.x, a.y - b.y) < a.r + b.r;

const inBlast = Math.abs(p.x - bomb.x) < bomb.size / 2 + p.r &&
                Math.abs(p.y - bomb.y) < bomb.size / 2 + p.r;

Drawing a spike: gradient trail + triangle

The trail is a thin rectangle filled with a vertical gradient from transparent to purple, which reads as speed. The head is a three-point path. Everything is redrawn from scratch each frame after clearRect.

const g = ctx.createLinearGradient(0, s.y - s.len, 0, s.y);
g.addColorStop(0, "rgba(168,85,247,0)");
g.addColorStop(1, "rgba(168,85,247,.9)");
ctx.fillStyle = g;
ctx.fillRect(s.x - 1.5, s.y - s.len, 3, s.len);

Sound design from two building blocks

tone() is an oscillator with an optional pitch slide; noise() is filtered static with an optional filter sweep. Every effect is a recipe of those:

star:  tone(880 → 1320, triangle, 0.12s) + a fifth above, 60ms later
       (pitch rises a semitone per star if you chain them within 2.5s)
hit:   noise(lowpass 600 → 80Hz, 0.3s) + tone(160 → 50Hz, sine)
tick:  tone(1400Hz, square, 0.03s)   (ticks speed up as the fuse burns)
boom:  noise(lowpass 1200 → 60Hz, 0.7s) + tone(110 → 30Hz, sine)
phase: tone(300 → 900Hz, sine, 0.25s)
over:  tone(440 → 110Hz, triangle, 0.8s) + noise tail

Fair on every device

Touch works by dragging anywhere (the dot follows your finger without scrolling the page), and the arrow keys/WASD move the crosshair for keyboard players. Switching tabs or pressing Esc pauses. With prefers-reduced-motion, the screen shake and particle bursts are turned off.

Other ways to build it

  • Kaboom / PhaserGame frameworks with sprites, collisions and scenes built in. Great once a game has many rules.
  • PixiJSA fast WebGL renderer if you want hundreds of particles and glow effects.
  • Supabase / FirebaseAdd the original's global high scores with a tiny database table.
  • Howler.jsPlay recorded sound files instead of synthesising them.
