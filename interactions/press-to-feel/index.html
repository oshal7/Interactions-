How it's built

One button, five small tricks.

It looks like one effect, but it's really five separate pieces timed to happen together: a 3D key, a press, a colour that spreads out from the key, a blurred text swap, and a click sound. None of them needs a library. Everything below is in main.js and style.css in this folder.

What I saw in the original (from a screen recording)

Ingredients

  • HTML <button>Gives you keyboard support, focus and screen-reader semantics for free.
  • CSS custom propertiesEvery value you can tune (angles, colours, timing) is a variable, so JS just sets numbers.
  • CSS 3D transformsperspective, rotateX/Y/Z make a flat div read as a physical key.
  • clip-path: circle()Masks a full-screen colour layer to a growing circle, so the colour spreads out.
  • Web Animations APIelement.animate() runs the reveal and tells you when it's done.
  • CSS filter + grid stackingTwo headlines in one grid cell, blurred in and out.
  • Web Audio APIGenerates the click from noise; no audio files, tunable live.
  • Pointer + keyboard eventsSeparate “down” and “up” so the key sinks and clicks at the right moments.
  • Container queriescqi units size the type to the stage, not the window.
  • prefers-reduced-motionRemoves the movement for people who've asked for less of it.

A two-state machine

Everything hangs off one attribute. JS flips it; CSS decides what each state looks like. That keeps the logic tiny and lets every part (key colour, headline, hint) react to the same switch.

<section class="stage" data-state="a">…</section>

.stage[data-state="a"] { --cap: var(--cap-a); --ink: var(--ink-a); }
.stage[data-state="b"] { --cap: var(--cap-b); --ink: var(--ink-b); }

stage.dataset.state = state === "a" ? "b" : "a";

The keycap: two layers and some perspective

The key is a .key-base (darker, pushed down by --depth) with a .key-cap sitting on top. The base colour is mixed from the cap colour, so one colour picker updates both. The whole button is tilted in 3D; the slant you control in the panel is just --rz.

.key {
  transform: perspective(900px)
             rotateX(var(--rx)) rotateY(var(--ry)) rotateZ(var(--rz));
  /* overshoot curve = a little wobble when it re-angles */
  transition: transform 700ms cubic-bezier(.34, 1.4, .64, 1);
}
.key-base { transform: translateY(var(--depth));
            background: color-mix(in oklab, var(--cap) 45%, #050508); }

The press: down and up are separate moments

A real key reacts when your finger lands, not when you let go. So the cap sinks on pointerdown (with a very fast 60 ms transition) and the state flips on pointerup. Pointer capture means dragging off the key cancels cleanly instead of leaving it stuck down.

key.addEventListener("pointerdown", (e) => {
  key.setPointerCapture(e.pointerId);
  key.classList.add("is-down");     // cap sinks
  sfx.press();                      // first tick
});
key.addEventListener("pointerup", (e) => {
  key.classList.remove("is-down");  // cap springs back
  sfx.release();                    // second tick
  toggle(e);                        // flip the state
});

.key.is-down .key-cap { transform: translateY(calc(var(--depth) * .8)); }

The colour spread: a growing circle mask

A full-size layer painted in the next colour sits above the background, masked to a circle of radius 0 at the key's centre. We animate the radius to the distance from that point to the farthest corner (Math.hypot), so it always covers the stage exactly. When it finishes, the colour is copied to the base layer and the mask resets, ready for the next press.

const R = Math.hypot(Math.max(x, w - x), Math.max(y, h - y));
reveal.style.background = nextColor;
const anim = reveal.animate(
  [{ clipPath: `circle(0px at ${x}px ${y}px)` },
   { clipPath: `circle(${R}px at ${x}px ${y}px)` }],
  { duration, easing, fill: "forwards" }
);
anim.onfinish = () => { bg.style.background = nextColor; anim.cancel(); };

If you press again mid-animation, the running reveal is finished instantly first, so fast presses never leave the scene in a half-state.

The headline swap: stack, blur, fade

Both headlines are always in the DOM, stacked in the same grid cell so they occupy the same spot. The hidden one gets opacity: 0, a 14px blur and a slight shrink. Swapping state transitions all three, which is why you briefly see both, out of focus, while they cross.

.headline { display: grid; }
.hl { grid-area: 1 / 1; transition: opacity .45s, filter .45s, transform .45s; }
.stage[data-state="a"] .hl-b,
.stage[data-state="b"] .hl-a { opacity: 0; filter: blur(14px); transform: scale(.97); }

The sound: a synthesised switch

A mechanical switch click is mostly a burst of noise with energy around one frequency. So we take 80 ms of white noise, push it through a bandpass filter at the chosen pitch (3.3 kHz to match the reference), and shape its volume to spike in 1 ms and die in ~18 ms. A tiny random playback-rate wobble makes repeat clicks sound less robotic. “Thocky” and “Soft pop” add a low sine wave for body. All of it lives in assets/js/sound.js so other patterns can reuse it.

const band = ctx.createBiquadFilter();
band.type = "bandpass"; band.frequency.value = 3300; band.Q.value = 3.5;

amp.gain.setValueAtTime(0.0001, t);
amp.gain.exponentialRampToValueAtTime(volume, t + 0.001);  // attack
amp.gain.exponentialRampToValueAtTime(0.0001, t + 0.018);  // decay

noise.connect(band).connect(amp).connect(ctx.destination);
Browsers block audio until the user interacts with the page, so the AudioContext is created on the first press. Since that press is a gesture, it just works, with no “enable sound” prompt needed.

Keyboard, screen readers and reduced motion

Space and Enter mirror the pointer: keydown sinks the key and plays the first tick, keyup releases it and flips the state (held-key auto-repeat is ignored). aria-pressed reflects the state, the headline sits in an aria-live region, and with prefers-reduced-motion the reveal becomes an instant swap.

Other ways to build it

  • View Transitions APIdocument.startViewTransition() + a clip-path keyframe on ::view-transition-new(root) gives the same circle reveal for a whole page or theme.
  • Recorded samplesRecord a real switch (down + up as two files) and play them with Web Audio or Howler.js. More realistic, but adds downloads.
  • GSAP / MotionHandy if you sequence many steps, but nothing here needs more than CSS transitions and element.animate().
