ASCII pet

A little creature made of text lives at the bottom of the page. Pick a tool: feed (hold or shake to pour berries), pet (rub it), or wake (ring the bell). Care adds up, and it grows from an egg into one of three final forms, depending on how you looked after it. Sound on!

How it's built

      
A pet made of plain text.

      
The inspiration is a portfolio footer where your cursor becomes a watering can and a row of ASCII sprouts
        grow into flowers as you water them. This pattern keeps that mechanic (the cursor is a tool, care adds up, and each threshold
        swaps in a bigger drawing) and gives it to a creature that walks, eats, sleeps and reacts.


      
From the garden to the pet

Ingredients

      
    
        
  • A character grid on <canvas>Measure one character of a monospace font, divide the canvas into cells, and draw everything at whole cells.
    • 
        
  • Sprites as stringsEach stage is a few lines of text. Placeholders 1 2 3 mark the eyes and mouth so one drawing can show every mood.
    • 
        
  • A small state machineidle → walk → eat, sleep, surprised, dance and evolve, each with its own face and timer.
    • 
        
  • Needs that driftFood and rest slowly drop over time; low food sends it looking for berries, low rest puts it to sleep.
    • 
        
  • Growth thresholdsEvery act of care adds a point; the stage changes when the points pass the next threshold, like water filling a flower.
    • 
        
  • Glyph scrambleEvolving dissolves the old drawing into random glyphs and types the new one in, cell by cell.
    • 
        
  • Grid-snapped particlesFood falls with real physics, but is drawn at the nearest cell, so it reads as text.
    • 
        
  • Web Audio synthNom, purr, a hand bell, snores and an evolve chime, all synthesised. Smaller stages have higher voices.
    • 
        
  • localStorageYour pet (stage, care, food, rest) is saved, and a little hungrier when you come back.
    • 
      


      

        

          

            
The grid

            
Measure the width of one character in the mono font, then every position becomes a column and a row. Things can
              move smoothly underneath, but they're always drawn at whole cells, which is what makes it feel like text.


ctx.font = `500 ${fs}px "JetBrains Mono", monospace`;
cw = ctx.measureText("M").width;    // cell width
ch = Math.round(fs * 1.3);          // cell height
const put = (col, row, text, color) => {
  ctx.fillStyle = color;
  ctx.fillText(text, col * cw, row * ch);
};

          

        


        

          

            
One drawing, every mood

            
Each stage is a few strings. 1 and 2 are the eyes, 3 is the mouth; they're
              swapped for the mood's characters every frame. Shifting both eyes one column left or right makes it look at the
              cursor or the food.


budlet: [
  "   \\v/   ",
  "  .-|-.  ",
  " ( 1 2 ) ",
  " /`-3-'\\ ",
  '   " "   ',
]
FACES = { idle: ["o","o","-"], happy: ["^","^","w"],
          eat: [">","<","o"], sleep: ["-","-","."],
          surprised: ["O","O","o"], hungry: ["o","o","n"] }

          

        


        

          

            
Care becomes growth

            
The same mechanic as the watered flowers. A berry eaten while hungry, a few seconds of petting, or playing when
              it's awake each add one point. When the total passes the next threshold, it evolves. Petting has a small budget
              that refills over time, so frantic rubbing can't skip a stage in two seconds.


const NEED = [6, 20, 44, 80];      // total care to leave each stage
if (pet.xp >= NEED[pet.stage] / growthSpeed) startEvolve(pet.stage + 1);

// the final form follows how you cared for it
const best = ["love", "fed", "play"].reduce((a, k) => care[k] > care[a] ? k : a);
pet.form = { love: "heartbloom", fed: "plumbloom", play: "starbloom" }[best];

          

        


        

          

            
A tiny state machine

            
Every frame the creature is in exactly one state, and each state has a face, a timer and a way out. Needs push it
              between states: low food makes it walk to the nearest berry, low rest (or being left alone) puts it to sleep, and
              the bell wakes it, grumpily if it hasn't slept enough.


idle ──food on the ground──▶ walk ──reached it──▶ eat ──▶ idle
idle ──rest low / ignored──▶ sleep ──rested──▶ idle
sleep ──bell──▶ surprised ──rested enough?──▶ dance │ back to sleep
idle ──bell──▶ dance ──▶ idle
idle ──care ≥ threshold──▶ evolve ──▶ idle (next stage)

          

        


        

          

            
The evolve scramble

            
Every cell gets a fixed random number. In the first half of the animation, cells whose number is below the progress
              turn into random glyphs; in the second half, the new drawing's cells appear in that order. Spaces stay empty, so the
              silhouette stays readable.


const k = ((r * 73 + c * 151) % 97) / 97;   // fixed order per cell
if (p < 0.5) cell = k > p * 2 ? oldCell : randomGlyph;
else          cell = k < (p - 0.5) * 2 ? newCell : randomGlyph;

          

        


        

          

            
The tools are the cursor

            
The real cursor is hidden over the canvas, and the tool is drawn at the pointer and rotated with the canvas. The
              berry bag tilts when you hold the button or shake it, and berries come out of its corner wherever the tilt has put it.
              The hand counts how far you rub over the pet; the bell swings with a damped sine.


const pouring = pointer.down || pointer.speed > 900;
// spout = bag corner, rotated by the current tilt
const sx = px + lx * cos(a) - ly * sin(a);
const sy = py + lx * sin(a) + ly * cos(a);

bellAngle = sin(t * 22) * 0.55 * exp(-t * 4);

          

        


        

          

            
Sound

            
Built from the lab's two synth blocks, tone() and noise(), with a short room reverb. Its
              voice drops as it grows.


nom:    2 × (noise 900 → 300Hz + triangle 330 → 220Hz), 150ms apart
purr:   noise 240 → 140Hz + 62Hz sine + a tiny high blip
bell:   1180Hz × [1, 2.76, 5.4], higher partials die first
snore:  slow-attack noise 260 → 150Hz
evolve: rising pentatonic run, longer for later stages

          

        

      


      
Other ways to build it

      
    
        
  • A <pre> per spriteFine for one creature: put the frame in a <pre> and colour spans. Particles get harder.
    • 
        
  • A DOM grid of spansOne span per cell makes every character selectable and searchable, at a higher cost per frame.
    • 
        
  • A font atlas in WebGLFor thousands of characters (a whole ASCII world), draw glyphs from a texture in a shader.
    • 
        
  • Image to ASCIIMap pixel brightness to @%#*+=-:.  to turn drawings or a webcam into sprites.
